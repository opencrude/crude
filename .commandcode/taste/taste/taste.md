# Taste
- Values data persistence across app restarts — session history (including previously terminated sessions) must remain browsable after quitting and reopening the app; treats losing it as a bug. Confidence: 0.8
- Likes stateful, at-a-glance UI affordances: animated icons for running agents vs static icons for paused/stopped ones, and session listings enriched with status (terminated / working / minimized) and sub-agent counts plus other useful metadata. Confidence: 0.7
- Communicates UI feedback with screenshots and pasted terminal/test output, and reasons about codebase internals in technical terms (layout invalidation, hit testing, per-frame relayout). Sent another screenshot to demonstrate a UI bug (session picker missing history). Confidence: 0.8
- Develops a Go bubble-tea TUI on Windows, running tests via `go test` piped through PowerShell (Select-String / Select-Object) to filter results. Confidence: 0.8
- Dislikes drawn-out diagnosis narration ("tracking/diagnosing/mapping why") without a delivered fix — when they ask "why won't you fix it?", they want immediate action, not more investigation updates. Prefers concise acknowledgment then a fix. Confidence: 0.6
- Explicitly asks for no speculation: wants the agent to take its time, examine the actual code/evidence, and deliver fixes that are effective and verifiable (e.g., confirmed by tests or demonstrable output) rather than guessed or asserted. Confidence: 0.8
- Runs the app during development with `go run .` and verifies fixes by restarting the app to check behavior across runs (found the missing-session bug exactly this way; re-reported the paste bug "happened again on my new go run ."). Confidence: 0.6
- Wants key interactive UI elements (e.g., the footer button) to be visually noticeable — asked to "make that button more noticeable," approving a distinct background color so it pops instead of blending into the surrounding pane. Confidence: 0.7
- Considers it correct-by-design that sessions with no turns are not persisted (empty sessions should be cleaned up, not saved) — confirmed the app was "behaving correctly" and that history loss was a config issue, not a bug. Confidence: 0.6
- Self-diagnoses and fixes issues himself, then explicitly closes the topic ("no further action required") and expects the agent to drop it and pivot to the remaining ask (e.g., the cosmetic UI change) without re-investigating. Confidence: 0.5
- Gives terse, symptom-level follow-up reports after testing a fix ("it now reacts to click and edit but the parent doesn't get edited", "i did ctrl + v it didnt shown me a thing then i did arrow left and it actually showed it"), expecting the agent to retain full context and keep fixing the remaining part of the flow end-to-end (including cascading state, not just the immediate component) without re-explanation. Confidence: 0.7
- Cares that fixes are "clean" so they don't cause trouble later — wants durable, minimal, pattern-consistent fixes (e.g., marking a window dirty the same way sibling event paths already do) rather than one-off patches or hacks. Confidence: 0.6
- Expects interactive affordances to be visually consistent app-wide: resize hover highlighting that exists on some draggable chrome (split dividers, top border) must apply to all resizable borders/corners (left/bottom/right) — hover feedback is "distinct and useful" for discoverability, and its absence on a functional-but-unhighlighted edge is a bug to fix. Confidence: 0.6
