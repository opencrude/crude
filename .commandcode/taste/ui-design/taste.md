# UI Design Taste

- Hates decorative prefix glyphs (❯, ▸, `>`, `•`) before selectable/list items anywhere — selection must be indicated only by hover/selected background change and content must start immediately. Wants this enforced globally, including in design docs, so future agents never use such glyphs. Confidence: 0.9
- Buttons should have a distinct background only on hover; in the resting state they should use a distinct font color on the matching background, and hover must adaptively invert background/text so it stays readable. Confidence: 0.9
- Every interactive element (buttons, form items, list/menu items) in every surface must be reachable and cyclable with arrow keys — app-wide keyboard navigation, in forms, docks, and menus alike. Confidence: 0.9
- Filter/search inputs must always have their own distinct background color, consistently everywhere (lists, file tree, recent workspaces, providers/models). Confidence: 0.9
- Search/filter boxes should place the magnifying-glass icon at the end, not the start. Confidence: 0.7
- Dropdowns must support search/filtering, and selecting an item must not immediately commit the change (e.g., picking a model needs a separate select/filter state) — a single click should not silently alter the used model. Confidence: 0.8
- Settings are organized as a three-tier override hierarchy (app → workspace → model/agent) like JetBrains: workspace inherits app settings (must not hard-copy them), agent settings stay stable. Confidence: 0.8
- Settings/session titles should be breadcrumb-style ("Session Settings . X . Y") for any depth of hierarchy; list content aligned in table-like columns (dots/separators exactly under each other; model name before provider). Confidence: 0.8
- Wants lean, compact, "orderly and neat" design — hates gigantic/bloated elements, filler glyphs, redundant panel titles, and wasted columns; spacing must be symmetric and dynamically computed from the available width. Confidence: 0.9
- Never restyle things that weren't asked about (e.g., "who told you to change scrollbar thumb and tracks?") — unrequested cosmetic changes are treated as damage. Confidence: 0.9
- Uses VS Code, JetBrains, and Cursor as the design reference: activity-bar gear opening app settings, per-panel context menus, docs opening on the right, terminal-style "new tab" buttons, content-sized tabs with working close buttons, and VS Code/JetBrains-level feature sophistication (git blame, exact-line edits, LSP diagnostics, agents tree). Confidence: 0.9
- Menu items need consistent, beautiful font/foreground coloring globally, with spacing between items dynamically calculated from the available width. Confidence: 0.8
- Action buttons should sit on the right side of panels; separator lines should separate settings items from buttons and run all the way across. Confidence: 0.7
- Dropdowns need z-index/overlay behavior (they must not push content down), and settings/modal panels need stable on-demand scrollbars rather than always-on ones. Confidence: 0.8
- Uses orange as the brand accent for active/selected states (e.g., the workspace↔application switch font color "to our orange"). Confidence: 0.6
- Terminal cursor should blink only when idle and stop blinking on any input/state change. Confidence: 0.8
- Panel headers should be minimal (icon only, then search immediately — no redundant title), with hover highlight filling the full panel width symmetrically and a clear separator before content. Confidence: 0.8
- Demands "common sense and taste in design" — design as if the user themselves would use or buy the software; exceptional results, not the easiest path. Confidence: 0.9
- Interaction behavior must be identical across analogous surfaces (e.g., scrollbar control in the git panel must work exactly like the file explorer's); when a control works in one panel but not another, treat it as a potential general issue and resolve the root cause completely everywhere, not just at the reported spot. Confidence: 0.8
